# 서울 부동산 실거래가 수집·적재

국토교통부 실거래가 공개 API에서 서울 25개 자치구와 경기 49개 시군구의 최근 5년치 거래를
받아 SQLite에 쌓고,
집계 패널을 만들어 CSV로 내보낸다.

## 무엇을 받나

| 소스 키 | API | 유형 | 거래 |
|---|---|---|---|
| `apt_trade` | RTMSDataSvcAptTradeDev | 아파트 | 매매 |
| `apt_rent` | RTMSDataSvcAptRent | 아파트 | 전월세 |
| `rh_trade` | RTMSDataSvcRHTrade | 연립다세대 | 매매 |
| `rh_rent` | RTMSDataSvcRHRent | 연립다세대 | 전월세 |
| `offi_trade` | RTMSDataSvcOffiTrade | 오피스텔 | 매매 |
| `offi_rent` | RTMSDataSvcOffiRent | 오피스텔 | 전월세 |

6종 × 74개 시군구(서울 25 + 경기 49) × 61개월. 백지에서 받으면 개발계정 일일 트래픽
10,000회를 훨씬 넘으므로, 주간 크론은 `--refresh-recent 3`으로 최근 세 달만 다시 받는다.

기본 수집 창은 **당월을 끝으로 하는 61개월**이다. 2026-08-30 전에는 전월이 끝이었는데, 신고
기한 30일은 월 집계에 넣지 말아야 할 이유이지 받지 말아야 할 이유가 아니었다. 받아 두면
진행 중인 달은 월 통계에서 빠지고 개별 거래 목록에만 잠정으로 실린다.

## 1. 인증키

[공공데이터포털](https://www.data.go.kr)에서 위 6개 API를 각각 활용신청한다. 승인은 보통 즉시 난다.
마이페이지의 **일반 인증키(Decoding)** 를 쓴다.

```bash
git clone https://github.com/Aliasss/estate_pj.git
cd estate_pj
pip install -r requirements.txt

export MOLIT_SERVICE_KEY="발급받은 Decoding 키"
```

Encoding 키를 넣어도 스크립트가 알아서 되돌리므로 둘 중 아무거나 넣어도 된다.
Python 3.9 이상이면 되고, 외부 의존성은 `requests` 하나뿐이다.

로컬에서 안 돌리고 GitHub Actions로 돌려도 된다. Settings → Secrets and variables → Actions에
`MOLIT_SERVICE_KEY`를 넣고 Actions 탭에서 `서울 실거래가 수집`을 수동 실행하면 집계 CSV가
아티팩트로 떨어진다. 이후 매주 월요일 21:00 UTC(화요일 06:00 KST)에 자동으로 최근
3개월을 다시 받는다.

## 2. 수집

```bash
python collect.py --db seoul_rt.sqlite
```

- 6종 전부, 74개 시군구 전부, 최근 61개월. 백지에서 받으면 일일 쿼터를 넘기므로 며칠에
  나눠 받게 된다. 주간 크론은 최근 세 달만 다시 받아 1,332구간을 약 90분에 끝낸다.
- 중단해도 된다. `fetch_log`에 (소스, 구, 계약년월) 단위로 진행 상황이 남아 재실행하면 이어서 받는다.
- `<item>`의 모든 자식 태그를 `payload` JSON 컬럼에 통째로 넣는다. API가 필드를 추가·개정해도
  스크립트가 깨지지 않고, 정규화 컬럼은 그 위에 얹은 편의 계층일 뿐이다.

자주 쓰는 옵션:

```bash
python collect.py --start 202108 --end 202607        # 기간 지정
python collect.py --sources apt_trade,apt_rent       # 소스 지정
python collect.py --lawd 11680,11650                 # 강남·서초만
python collect.py --max-calls 3000                   # 일일 트래픽 보호
python collect.py --refresh-recent 3                 # 최근 3개월 재수집 (신고 지연 반영)
```

인증키 오류·할당량 초과(`resultCode` 30, 22 등)는 재시도해도 소용없으므로 즉시 중단한다.
네트워크 오류와 일시적 5xx는 지수 백오프로 5회까지 재시도한다.

## 3. 집계

```bash
python aggregate.py --db seoul_rt.sqlite --csv-dir ./out
```

만들어지는 테이블:

- **`monthly_panel`** — 월 × 시군구 × 유형 × 거래유형. 최대 27,084행.
  거래건수, 해제건수, 전세/월세 건수, 신규/갱신 건수, 중위 거래금액, 중위 평단가, 평균 전용면적, 평균 준공연도
- **`jeonse_ratio`** — 월 × 시군구 × 유형. 최대 13,542행.
  중위 매매가, 중위 전세보증금, **전세가율** (금액 기준 / 평단가 기준 두 가지)
- **`monthly_coverage`** — 월 × 유형 × 거래유형 총 건수. 신고 누락 점검용

집계 규칙:

- 해제된 거래(`cdealType = 'O'`)는 통계에서 빼고 `n_cancelled`에 건수만 남긴다.
- 평균이 아니라 **중위값**을 쓴다. 실거래가는 초고가 거래 몇 건에 평균이 크게 흔들린다.
- 평단가는 **전용면적** 기준(`금액 / (전용면적 / 3.305785)`). 공급면적 기준 평단가보다 20~30% 높게 나오니
  부동산 앱 숫자와 직접 비교하지 말 것.
- 전세가율은 금액 기준(`jeonse_ratio_amount`)과 평단가 기준(`jeonse_ratio_ppp`)을 모두 낸다.
  구별 전세 물건이 매매 물건보다 작은 평형에 몰리는 편이라, 면적 믹스를 통제한 **평단가 기준이 더 정확하다.**

CSV는 UTF-8 BOM으로 나가므로 Excel에서 바로 열리고 Google Sheets 임포트도 깨지지 않는다.

## 4. 데이터가 어디에 남나

**원본은 SQLite 파일 하나가 종착지다.** 150~200만 행에 인덱스까지 합쳐 1GB 안팎이라 외부 DB로
옮길 이유가 없고, 물건 단위 분석(전세가율, 담보여력, 같은 단지 매매-전세 페어링)은 SQLite에서
그대로 된다.

```bash
sqlite3 seoul_rt.sqlite
sqlite> SELECT * FROM deals WHERE sgg_nm='강남구' AND ym='2026-06' LIMIT 5;
```

**집계 패널은 CSV로 내보내 스프레드시트에 올린다.** `monthly_panel` 27,084행 × 15열 = 41만
셀로 Google Sheets 1,000만 셀 한도에 한참 못 미친다. CSV는 UTF-8 BOM으로 나가므로 Excel에서 바로
열리고 Sheets 임포트도 한글이 깨지지 않는다.

원본 150만~200만 행은 Excel 시트당 104만 행 한도에도, Sheets 셀 한도에도 안 들어가므로
스프레드시트에 올리지 말 것.

### Actions로 돌릴 때

러너 디스크는 잡이 끝나면 파기되므로 결과를 세 군데로 빼놓는다.

| 위치 | 내용 | 보존 |
|---|---|---|
| `data/*.csv` | 집계 패널 3종 | 리포지토리에 커밋. 영구 + 월별 변화가 git 히스토리에 남는다 |
| 릴리스 `data-latest` | 원본 SQLite (gzip, 300MB 안팎) | 만료 없음. 다음 실행이 여기서 이어받는다 |
| 아티팩트 | 집계 패널 3종 | 30일. 웹에서 바로 받을 때 편의용 |

Actions 캐시를 안 쓰는 이유: 캐시는 **7일 미접근 시 삭제**된다. 주간 스케줄이 정확히 그
경계에 걸려서, 한 회차만 밀려도(실측 지각 26~42분, 실패 시 며칠) 캐시가 사라진 뒤에 돈다.
그러면 5년치를 처음부터 다시 받는다. 이 스케줄이 월 1회였을 때는 항상 만료였고, 주간이 된
지금은 늘 아슬아슬하다. 어느 쪽이든 기댈 것이 못 된다. 릴리스 자산은 만료가 없어서
`--refresh-recent 3`이 의도대로 동작한다.

수집이 중간에 깨져도 받은 만큼은 릴리스에 올라가므로, 재실행하면 이어받는다.

### 차단으로 실패했을 때는 사람이 다시 눌러야 한다

국토부 게이트웨이는 GitHub 러너를 **IP 단위로** 막는다. 2026-08-25 정찰에서 한 러너의 실거래
여섯 서비스와 건축물대장까지 일곱이 전부 ConnectTimeout인 그 시각에, 다른 러너의 대장 크론은
정상으로 수집하고 있었다. 같은 호스트, 같은 인증키, 같은 시각인데 러너 IP만 달랐다.

그래서 같은 잡에서 기다리는 것은 값이 없다. 사전 확인은 3분 만에 접고 종료 코드 75로 끝나며,
로그가 그 사실을 밝힌다. **자동 재시도는 아직 없다.** Actions 탭에서 `서울 실거래가 수집`을
다시 실행하면 새 러너가 다른 IP를 뽑는다. 실측으로 8/24 크론과 8/25 재시도가 연달아 막힌 뒤,
새 잡으로 돌린 회차는 사전 확인을 첫 시도에 통과해 11분 만에 끝났다.

주간 크론이 차단되면 다음 크론은 이레 뒤다. 그동안 화면은 "받았어야 할 실거래 자료를 아직
받지 못했습니다"라고 밝히지만, 채우는 것은 사람이 눌러야 한다.

원본을 로컬로 가져오려면:

```bash
gh release download data-latest --repo Aliasss/estate_pj
gunzip seoul_rt.sqlite.gz
```

`data/*.csv`는 Google Sheets에서 `IMPORTDATA`로 raw URL을 직접 물려도 된다.

## 데이터 함정

**전월세는 2021년 6월 임대차신고제부터다.** 그 이전 자료는 확정일자 신고분 기반이라 모집단이 다르다.
게다가 계도기간이 세 차례 연장돼 **2021.06.01 ~ 2025.05.31까지 4년간** 과태료가 부과되지 않았고,
과태료는 2025.06.01 이후 체결된 계약부터 적용된다. 이 구간 신고 건수는 실제 거래보다 과소집계돼 있다.

최근 5년 창(2021.08~2026.07) 중 **46개월이 계도기간, 14개월만 의무 구간**이다. 즉 이 패널은
관측 강도가 도중에 한 번 바뀐다. `monthly_coverage`로 월별 건수 추이를 먼저 보고 2025.06 전후에
계단식 점프가 있는지 확인할 것. 있다면 **전월세 거래량 추세는 그 단절을 통제하지 않고 해석하면 안 된다**
(2025.06 전후를 나눠 보거나, 계도기간 구간만으로 추세를 잡는 식). 가격 통계(중위값)는 표본 편향이
덜하지만 영향이 없다고 볼 수는 없다. 매매 실거래가 신고는 2006년부터라 이 문제가 없다.

**신고 지연.** 계약일 기준 30일 이내 신고라서 최근 1~2개월 건수는 계속 늘어난다.
`--refresh-recent 3` 으로 주기적으로 다시 받아야 한다. 주간 크론이 쓰는 값이 그것이다.

**해제 거래.** 신고 후 해제된 건은 `cdealType='O'`로 남아 있다. 집계에서는 제외했지만 원본에는 있다.

**직거래.** `dealing_gbn`이 '직거래'인 건은 특수관계인 간 저가 거래가 섞여 있다.
가격 분석 시 필터링을 검토할 것.

## 웹앱 (PWA)

`web/`에 Vite + React PWA가 있다. 설치형이고 오프라인에서 동작한다 — 이 데이터를 실제로
꺼내 보는 순간은 책상이 아니라 집을 보러 간 현장이기 때문이다.

```bash
cd web
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

`npm run build`는 먼저 `scripts/fetch-data.mjs`를 돌려 데이터를 `public/data`로 굽는다.

| 티어 | 출처 | 크기 | 로딩 |
|---|---|---|---|
| 1 | 커밋된 `data/*.csv` → `tier1.json` | 2.6MB (gzip 249KB) | 프리캐시. 오프라인 동작의 기반 |
| 2 | `data-latest` 릴리스의 `units.tar.gz` | 구당 gzip 112KB | 구를 열었을 때만 받고 캐시 |

티어 2를 릴리스로 돌리는 이유는 10MB급 파일을 매주 커밋하면 리포지토리가 그만큼씩 불어나기
때문이다. 로컬에서 `build_units.py`로 `../units`를 만들어 뒀다면 그쪽을 그대로 쓴다.

### Vercel 배포

프로젝트를 만들 때 **Root Directory를 `web`으로** 지정한다. 나머지는 자동으로 잡힌다
(프레임워크 Vite, 빌드 `npm run build`, 출력 `dist`). 주간 수집 워크플로가 `data/`를
커밋하면 Vercel이 그 푸시를 받아 자동 재배포한다.

### 차트 규칙

- 축이 다른 지표는 차트를 나눈다. 이중 축은 쓰지 않는다.
- 계열이 둘 이상이면 범례를 두고 선 끝에 직접 라벨을 붙인다. 색만으로 식별시키지 않는다.
- 평단가 계열은 `jeonse_ratio`에서 가져온다. `monthly_panel`의 '전월세'에는 월세 보증금이
  섞여 있어 전세가율 차트와 숫자가 어긋난다.
- 신고 기한이 안 지난 달은 회색 음영 + '잠정' 표기. 신고 지연 구간을 시장 변화로 오독하면
  안 된다. 몇 달이 잠정인지는 날짜에 따라 하나이거나 둘이므로 숫자로 적지 않는다.
