# 수익 모델 검토 (2026-08, 결정 보류)

> 상태: **아카이브. 결정하지 않았다.** 광고 포함 어떤 수익 모델도 붙이지 않기로
> 한 상태에서, 훗날 논의를 다시 열 때의 출발점으로 당시 검토 내용을 남긴다.

## 대원칙

**돈이 세입자 쪽에서 나와야지, 집을 파는 쪽에서 나오면 안 된다.**

"팔 것이 없어서 위험을 말할 수 있다"가 이 서비스의 정체성이다. 중개·분양·임대인
쪽 수익이 붙는 순간 존재 이유가 무너진다. 아래 모든 후보는 이 원칙으로 걸렀다.

## 광고 (보류됨)

기술적으로는 하루 작업이지만 세 가지 장벽으로 보류했다.

- **도메인**: 애드센스는 `*.vercel.app` 무료 서브도메인을 승인하지 않는다.
  커스텀 도메인이 선행 조건. 카카오 애드핏은 문턱이 낮고, 쿠팡 파트너스는
  승인 부담이 거의 없다.
- **개인정보처리방침**: 광고는 쿠키·추적을 데려온다. "개인 데이터를 서버에
  두지 않는다"가 강점인 서비스에 방침 페이지부터 만들어야 한다.
- **브랜드 충돌**: 부동산 서비스의 문맥 광고는 높은 확률로 분양·중개 광고다.
  위험 판정 옆에 신축 분양 광고가 뜨면 핵심 서사가 무너진다. 하게 되면
  카테고리 차단(부동산·금융)과 판정 화면(계약 전 확인) 광고 금지가 전제.
- 수익 현실: 배너는 트래픽 수만 단위 전까지 월 몇천~몇만원 수준.

## 후보 우선순위

### 1순위: 계약 시점의 유료 심화 리포트 (일회성 결제)

보증금은 전 재산이고 계약 직전은 지불 의사가 가장 높은 순간이다. 무료 검증
위에 "이 주소 종합 리포트"를 5천원~1만원대로 판다.

- 구성안: 실거래 심화 분석 + 등기부 확인 항목 대조 + 계약서 특약 문구 제안
  + 보관용 PDF
- 등기부 자동 열람은 유료 대행 API가 필요하다. 초기에는 사용자가 발급본을
  업로드하는 방식도 가능.
- 돈을 내는 사람과 서비스가 지키는 사람이 일치한다. 중립성 완전 보존.

### 2순위: "보증금 지킴이" 알림 구독 (월 소액)

현 서비스의 약점은 계약 순간에만 쓰이고 끝난다는 것. 계약 후 내 건물·동네의
위험 변화를 계속 감시해주는 구독이 이를 해결한다.

- 주간 배치가 이미 매주 재계산하므로, 내 건물이 깡통 기준에 걸리거나 동네
  역전세 비율이 뛰면 푸시로 알린다.
- PWA 푸시 + 건물 ID만 저장하면 되므로 "개인 데이터를 서버에 두지 않는다"
  원칙을 거의 훼손하지 않는다.
- 일회성 이용자를 반복 수익으로 바꾸는 유일한 경로.

### 3순위: B2B 데이터 API

건물 단위 깡통·역전세 판정은 현재 우리만 매주 자동으로 내는 데이터다.
전세대출 심사 금융사, 보증 리스크 기관, 프롭테크에 API로 판다.

- 단가와 천장은 가장 높지만 영업 사이클이 길다. 트래픽과 적중 사례가 쌓인
  뒤가 맞다.
- 서비스 화면을 건드리지 않으므로 정체성 충돌이 없다.

## 하지 않는 것

- 중개사 제휴("검증된 매물" 인증 발급), 분양·매물 광고, 임대인 쪽 과금 —
  전부 "파는 쪽 돈"이라 대원칙과 정면 충돌.
- 전세대출 비교 제휴는 경계선. 세입자 편익이지만 "결국 금융상품 파는 앱"으로
  읽힐 위험. 하더라도 리포트 안에서 정보로만 다룬다.

## 로드맵 (결정 시)

1번(심화 리포트)으로 결제 검증 → 2번(알림 구독)으로 반복 수익 → 트래픽·사례
축적 후 3번(B2B). 구체화 시 CPO·CTO 검토를 거쳐 리포트 구성안과 결제 연동
설계부터 잡는다.
